# Requirements — repo-scaffold

## Goal

Create the complete skeleton of the vitals-on-fhir repository: every package, module stub,
configuration file, and top-level file described in the steering documents, so that all future
feature specs can start from a structurally correct, lint-clean, type-check-clean baseline.

No business logic is implemented in this spec. Every Python file contains only the SPDX header,
a module-level docstring, the minimal imports required by its `__init__.py`/`__all__`, and
`...` (Ellipsis) or `pass` bodies on any classes or functions.

---

## Functional requirements

### FR-S1 — Python project tooling
- `pyproject.toml` is present, declares the project name (`vitals-on-fhir`), version (`0.1.0`),
  Python ≥ 3.12, and all runtime and dev dependencies listed in the tech steering doc.
- A `uv.lock` file is generated by `uv sync`.
- `ruff` is configured in `pyproject.toml` (line length 100, target Python 3.12, `src` layout).
- `mypy` is configured in `pyproject.toml` (strict mode, sources under `src/`).
- `pytest` is configured in `pyproject.toml`; the `hardware` marker is registered; the default
  test run excludes `hardware`-marked tests.
- The CLI entry point `vitals-on-fhir = "vitals_on_fhir.cli:main"` is registered in
  `[project.scripts]`.

### FR-S6 — CI
`.github/workflows/ci.yml` runs on every push and pull request and executes, in order:
1. `uv sync`
2. `uv run ruff check .`
3. `uv run mypy src`
4. `uv run pytest` (fast suite, no hardware marker)

## Non-functional requirements

### NFR-S1 — Zero lint errors
`uv run ruff check .` passes with no errors on the generated scaffold.

### NFR-S2 — Zero type errors
`uv run mypy src` passes with no errors on the generated scaffold.

### NFR-S3 — All tests pass
`uv run pytest` (fast suite) passes. This means `test_dependency_directions.py` passes — no
forbidden cross-package imports exist in the scaffold stubs.

### NFR-S4 — SPDX header
Every `.py` file in `src/` and `tests/` begins with `# SPDX-License-Identifier: AGPL-3.0-or-later`.

### NFR-S5 — No business logic
Stub modules must not contain any real implementation beyond frozen dataclass field declarations
and ABC method signatures with `...` bodies.
